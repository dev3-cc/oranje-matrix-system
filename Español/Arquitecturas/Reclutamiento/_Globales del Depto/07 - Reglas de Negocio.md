# 8. REGLAS DE NEGOCIO — DEPARTAMENTO DE RECLUTAMIENTO

---

| ID        | Regla                                         | Descripción                                                                                                                                                                                                                                                                            |
| --------- | --------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **RR-01** | Modelo Self-Pick colaborativo                 | Las requisiciones autorizadas no se distribuyen manualmente. Las Reclutadoras y los Líderes de Grupo las toman libremente desde la bandeja según su capacidad. Tomar una requisición ya tomada NO bloquea a los demás: varios reclutadores pueden trabajarla a la vez como reclutadores participantes. El Manager solo interviene en casos especiales (requisición varada, hotel VIP, balanceo, ausencia, corrección).         |
| **RR-02** | Consulta obligatoria de Blacklist             | Antes de asignar un candidato a una requisición, la Reclutadora o Líder DEBE consultar la Blacklist. Si el colaborador está vetado, el sistema bloquea la asignación con alerta visible.                                                                                               |
| **RR-03** | Cualquier rol agrega y levanta en Blacklist; el Administrador también | Cualquier rol del depto Reclutamiento (Reclutadora, Líder de Grupo, Manager) puede **agregar** a un colaborador a Blacklist desde **cualquier estado**, con motivo y evidencia obligatoria. También pueden **remover** (levantar el veto) los tres roles del depto y el Administrador (`ROL-ADM-01`), con motivo obligatorio, y el colaborador regresa a Blanco para ser revalidado *(cambiado el 2026-08-13; ampliado el 2026-10-10 por decisión de Hugo, con la advertencia de que quien pone el veto puede levantarlo)*. Las disputas (estado Rojo) las resuelve el **Inspector de zona**, no el Manager. |
| **RR-04** | Cobertura 100% para cierre                    | Una requisición no puede cerrarse como "Cubierta" si no tiene 100% de cobertura. El sistema bloquea el botón de cierre hasta que todas las posiciones estén al 100%.                                                                                                                   |
| **RR-05** | Exclusividad de colaborador                   | Un colaborador no puede estar en 2 hoteles **en las mismas horas**. Sí puede estar en dos el mismo día si los turnos no se solapan (precisado el 2026-08-12). Lo que el sistema bloquea siempre es que dos colaboradores tomen la misma plaza. Ver [[Arquitecturas/_Globales/Decisiones de Arquitectura\|D-19]] |
| **RR-06** | Captura de colaborador en 3 fases             | Fase 1: entrevista inicial por Reclutadora (nombre, edad, género, domicilio, teléfono). Fase 2: alta en app por el colaborador (posición, inglés, experiencia, transporte, modalidad — obligatorios; SSN, ITIN y documento de SSN/ITIN opcionales; sin SSN ni ITIN → retención 16% reembolsable activada automáticamente, ver [[Deducciones]]). Fase 3: datos de emergencia por el colaborador (contacto, tipo de sangre, alergias). |
| **RR-07** | Validación obligatoria post alta en app       | Tras Fase 2, la Reclutadora debe validar manualmente datos y documentos del colaborador antes de habilitarlo en el Pool.                                                                                                                                                               |
| **RR-08** | Habilitación de accesos automática            | Al validar al colaborador, el sistema propaga automáticamente los accesos a sus paneles en menos de 1 minuto.                                                                                                                                                                          |
| **RR-09** | Flujo de Reclutamiento continuo               | El proceso de reclutamiento es continuo. Reclutamiento siempre está contratando, haya o no requisiciones abiertas. Las requisiciones sin match aceleran prioridades pero no son condición para iniciar el flujo.                                                                       |
| **RR-10** | Jerarquía de supervisión                      | Manager de Reclutamiento → Líder de Grupo de Reclutadoras → Reclutadora. El Manager supervisa a los Líderes (no directo a las Reclutadoras). El Líder supervisa a su grupo.                                                                                                            |
| **RR-11** | Indicador de Lunch Extendido restringido      | El indicador de lunch extendido del Timesheet solo es visible para roles internos de Oranje (Inspector, Coordinador, Manager de Reclutamiento). NO es visible para el Hotel.                                                                                                           |
| **RR-12** | Trazabilidad de cambios excepcionales         | Toda intervención excepcional del Manager (asignar manual, forzar semáforo, agregar a Blacklist) queda registrada en log con motivo obligatorio.                                                                                                                                       |
| **RR-13** | Auto-asignación del Inspector por zona        | Al autorizarse una requisición, el sistema asigna automáticamente el Inspector correspondiente según la zona del hotel.                                                                                                                                                                |
| **RR-14** | Numeración automática de requisiciones        | Formato `AAAAMMDDHHMM + Homoclave` (ej. `202604081632V1`). Mismo formato para tarjetas de accidente laboral.                                                                                                                                                                           |
| **RR-15** | Modelo colaborativo de requisición            | Una requisición puede tener VARIOS reclutadores participantes trabajándola a la vez (no hay dueño único). Tomar una requisición ya tomada NO la transfiere ni la bloquea: el reclutador se UNE como participante adicional y nadie pierde la requisición. El avance de cobertura es COMPARTIDO entre todos los participantes y el lock de concurrencia opera a nivel de POSICIÓN/slot (dos reclutadores no asignan el mismo colaborador a la misma posición), no a nivel de la requisición completa. Salir retira solo al reclutador que sale; la requisición sigue En proceso si quedan otros participantes y solo vuelve a Autorizada cuando sale el ÚLTIMO reclutador.         |
| **RR-16** | Historial / trazabilidad de la requisición    | Cada requisición mantiene un Historial: un timeline cronológico INMUTABLE con ACTOR que registra quién la tomó / se unió, quién salió, quién asignó/desasignó qué colaborador a qué posición y quién la cerró, cada evento con timestamp + autor (rol y nombre). El Historial es visible para todos los reclutadores participantes, el Líder y el Manager.         |
